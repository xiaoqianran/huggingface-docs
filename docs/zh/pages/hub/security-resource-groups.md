# 具有资源组的组织中的高级访问控制

> [!警告]
> 此功能是团队和企业计划的一部分。

在 Hugging Face 组织中，您可以使用资源组来控制哪些成员有权访问特定存储库。

## 它是如何工作的？

资源组允许组织管理员将相关存储库分组在一起，从而允许组织中的不同团队处理独立的存储库集。

一个存储库只能属于一个资源组。

组织集合也可以分配给资源组，遵循与存储库相同的规则：集合只能属于一个资源组，并且可以由具有适当权限的成员在组之间移动。

需要将组织成员添加到资源组才能访问其存储库。一个组织成员可以属于多个资源组。

成员在每个资源组中分配有一个角色，该角色决定了他们对该组存储库的权限。资源组存在四种不同的角色：- `read`：授予对资源组内存储库的读取权限。
- `contributor`：为用户创建的组织存储库子集提供额外的写入权限（即，用户可以创建存储库，然后仅修改这些存储库）。与“写入”角色类似，但仅限于用户创建的存储库。
- `write`：提供对资源组中所有存储库的写访问权限。用户可以创建、删除或重命名资源组中的任何存储库。
- `admin`：除了存储库的写入权限之外，管理员成员还可以管理资源组 - 添加、删除和更改其他成员的角色。他们还可以管理资源组中现有的存储库。

此外，组织管理员可以管理组织内的所有资源组。这包括将存储库移入和移出任何资源组。资源组还会影响组织内部私有存储库的可见性。属于资源组一部分的私有存储库仅对该资源组的成员可见。另一方面，公共存储库对组织内部和外部的任何人都可见。相同的可见性规则适用于属于资源组的私有集合。

## 开始使用

转到您的组织的设置，然后导航到左侧菜单中的“资源组”选项卡。

    
    

组织管理员可以从该页面创建和管理资源组。根据组织的设置，角色较低的成员也可能被允许创建资源组（请参阅下面的[Who can create Resource Groups](#who-can-create-resource-groups)）。

创建资源组并为其指定有意义的名称后，您可以开始向其中添加存储库和用户。

    
    

> [!提示]
> 将用户添加到资源组时，您可以通过电子邮件地址搜索用户是否具有与您的组织电子邮件域匹配的组织特定电子邮件（例如，`user@your-company.com`）。请记住，一个存储库只能属于一个资源组。当您尝试添加已属于另一个资源组的存储库时，您会收到警告。

    
    

## 自动加入

自动加入会自动将**组织成员**添加到指定角色的资源组 - 启用自动加入时已在组织中的成员以及将来加入的任何新成员。

这对于整个组织都可以访问的资源组非常有用，而无需手动成员管理。

### 启用自动加入

**通过 UI**：打开资源组的设置页面并选中 **自动包含组织成员** 选项，然后选择要分配的角色。

**通过 API**：请参阅[Configure auto-join via API](./programmatic-user-access-control#configure-auto-join-via-api)。

在现有资源组上启用自动加入后，匹配所选范围的当前组织成员将**立即添加**到已配置角色的组中（回填）。

### 自动加入范围

自动加入可应用于：

- **所有组织成员**：包括每个成员，包括具有 `no_access` 组织角色的成员。
- **仅限读取+ 成员**：排除具有 `no_access` 组织角色的成员。当 `no_access` 成员应仅保留对手动或通过其他配置流程添加的特定资源组的访问权限时，请使用 **仅读取+ 成员**。

### 自动加入和 SCIM

自动加入和 SCIM 管理在同一资源组上**互斥**。自动加入自动添加组织成员； SCIM 管理意味着只有 IdP 控制成员资格。这两种行为是冲突的，所以：

- 您无法在链接到 SCIM 组的资源组上启用自动加入。
- 您无法将 SCIM 组链接到启用了自动加入的资源组。

要将资源组从自动加入切换到 SCIM 管理（反之亦然），请首先禁用当前设置。

## 谁可以创建资源组

默认情况下，只有组织管理员才能创建新资源组。组织管理员可以通过在资源组设置页面上设置创建资源组所需的**最低成员角色**来更改此设置。可用的选项有：
- **仅限管理员**（默认）- 只有组织管理员才能创建资源组。
- **写入** — 具有写入或管理员角色的成员可以创建资源组。
- **贡献者** — 具有贡献者、写入或管理员角色的成员可以创建资源组。
- **阅读+** — 任何组织成员都可以创建资源组。

当非管理员成员通过 UI 创建资源组时，他们会自动添加为该新创建组的 **管理员**。通过 API，这不会自动发生，因为 API 调用者可能代表其他人创建组。非管理员 API 调用者必须在组的初始成员列表中包含至少一名具有管理员角色的用户。

## 成本归因

> [!警告]
> 此功能是企业计划及以上版本的一部分。

资源组还充当计算服务的成本归属单位。当计算按资源组计费时，每个组的成本都会单独跟踪，从而更容易了解跨团队的支出。- **空间**：成本自动归因于空间所属的资源组。
- **作业**：创建作业时将资源组的 ID 作为 `namespace` 传递。参见[Bill to a resource group](./jobs-pricing#bill-to-a-resource-group)。
- **推理提供程序**：通过 `X-HF-Bill-To` 标头（或 SDK 中的 `bill_to` 参数）传递资源组的 ID。参见[Billing for Team and Enterprise organizations](/docs/inference-providers/pricing#billing-for-team-and-enterprise-organizations)。
- **推理端点**：成本自动归因于模型存储库所属的资源组。目前不支持直接从内置推理端点目录实例化的端点。

您可以使用专用 API 端点来检索资源组的成本归因数据。

## 资源组 API

您可以通过 Hub API 列出资源组并向其中添加用户（或更改成员的组织角色和资源组分配）。有关完整参考、示例和批处理工作流程，请参阅 [Programmatic User Access Control Management](./programmatic-user-access-control) 指南。
