# 用户访问令牌

## 什么是用户访问令牌？

用户访问令牌是向 Hugging Face 服务验证应用程序或笔记本的首选方式。您可以在[settings](https://huggingface.co/settings/tokens)中管理您的访问令牌。

访问令牌允许应用程序和笔记本执行由以下所示的角色范围指定的特定操作：

- `fine-grained`：具有此角色的代币可用于提供对特定资源的细粒度访问，例如特定组织中的特定模型或模型。这种类型的令牌在生产环境中非常有用，因为您可以使用自己的令牌，而无需共享对所有资源的访问权限。

- `read`：具有此角色的令牌只能用于提供对您可以读取的存储库的读取访问权限。这包括您或您所属的组织拥有的公共和私人存储库。如果您只需要从 Hugging Face Hub 读取内容（例如，下载私有模型或进行推理时），请使用此角色。- `write`：具有此角色的令牌还授予对您有写访问权限的存储库的写访问权限。如果您需要创建内容或将内容推送到存储库（例如，在训练模型或修改模型卡时），请使用此令牌。

如果您是具有读/写/管理员角色的组织成员，则您的用户访问令牌将能够根据令牌权限（读/写）和组织成员身份（读/写/管理员）读/写资源。

## 如何管理用户访问令牌？

要创建访问令牌，请转到您的设置，然后单击 [Access Tokens tab](https://huggingface.co/settings/tokens)。单击 **新令牌** 按钮创建新的用户访问令牌。

为您的代币选择一个角色和名称，然后瞧 - 您就可以开始了！

您可以通过单击“**管理**”按钮来删除和刷新用户访问令牌。

## 如何使用用户访问令牌？

有很多方法可以使用用户访问令牌来访问 Hugging Face Hub，为您提供在其上构建出色应用程序所需的灵活性。

用户访问令牌可以是：- 使用**代替密码**通过 git 或基本身份验证访问 Hugging Face Hub。
- 调用 [Inference Providers](https://huggingface.co/docs/inference-providers) 时作为 **不记名令牌** 传递。
- 用于 Hugging Face Python 库，例如 `transformers` 或 `datasets`：

```python
from transformers import AutoModel

access_token = "hf_..."

model = AutoModel.from_pretrained("private/model", token=access_token)
```

> [!警告]
> 尽量不要泄露您的令牌！尽管您始终可以轮换它，但任何人都可以同时读取或写入您的私人存储库，如果令牌已公开，请参阅[Revoking a leaked token](#revoking-a-leaked-token)。

### 最佳实践

我们建议您为每个应用程序或使用情况创建一个访问令牌。例如，您可以拥有一个单独的令牌：

- 本地机器。
- Colab 笔记本。
- 一个很棒的自定义推理服务器。

这样，您就可以使一个令牌失效，而不会影响您的其他用途。

我们还建议仅将细粒度令牌用于生产用途。如果泄露，影响将会减少，并且它们可以在您的组织之间共享，而不会影响您的帐户。例如，如果您的生产应用程序需要对门控模型的读取访问权限，您组织的成员可以请求对该模型的访问权限，然后创建具有对该模型的读取访问权限的细粒度令牌。然后可以在您的生产应用程序中使用该令牌，而无需授予其访问所有私有模型的权限。

### 对于 CI/CD 管道

如果您只需要从 CI/CD 工作流程（GitHub Actions、GitLab CI、CircleCI 等）进行访问，则可以完全避免将访问令牌存储为 CI 机密。请参阅 [Trusted Publishers](./trusted-publishers)，它会在每次运行开始时将 CI 提供商的 OpenID Connect (OIDC) 身份令牌交换为短期 Hub 令牌 - 要么是存储库范围（用于发布模型、数据集、空间或内核），要么是用户范围（用于读取您有权访问的门控存储库并获取帐户的速率限制）。

### 对于企业组织

如果您的组织需要以编程方式为成员颁发令牌而不要求每个用户创建自己的令牌，请参阅[OAuth Token Exchange](./oauth#token-exchange-for-organizations-rfc-8693)。此企业计划功能非常适合构建需要代表组织成员访问 Hugging Face 资源的内部平台、CI/CD 管道或自定义集成。

## 撤销泄露的令牌如果您自己的令牌之一已泄漏，请从设置的[Access Tokens tab](https://huggingface.co/settings/tokens)中删除或刷新它。

如果您发现了其他人的 Hugging Face 访问令牌，您可以使用 [⟦T7⟧](https://huggingface-openapi.hf.space/#tag/tokens/POST/api/credentials/revoke) 端点使其失效。您不需要对拥有该令牌的帐户或组织拥有任何权限。

```bash
# LEAKED_HF_TOKEN should contain the raw token value to revoke
curl -X POST "https://huggingface.co/api/credentials/revoke" \
  -H "Content-Type: application/json" \
  -d "{\"credentials\": [\"${LEAKED_HF_TOKEN}\"]}"
```

您可以在一次调用中传递`credentials`数组中的多个令牌值，这对于批量报告结果的秘密扫描管道来说很方便。

每个提交的与现有令牌匹配的令牌都会立即失效并在所有地方停止工作 - 与[organization-level revocation](./enterprise-tokens-management#revoking-via-api)不同，它只会切断令牌对单个组织的访问。令牌的所有者会收到电子邮件通知，需要创建新令牌才能恢复访问权限。

无论您提交的任何令牌是否存在，端点始终都会以 `202 Accepted` 进行响应，因此它的响应不能用于探测令牌是否有效。再次提交相同的令牌是无害的：重复调用不会执行任何操作，并且所有者只会收到一次通知。

> [!提示]
> 为了避免泄漏 shell 历史记录或日志中的令牌值，请通过环境变量或文件传递它们，并避免将原始令牌直接粘贴到命令行中。## 具有代币管理政策的组织中的代币

团队和企业计划的组织可以强制执行令牌策略，这些策略会影响您的令牌在访问该组织的资源时的工作方式。

### 当您的令牌需要批准时（团队和企业组织）

当您创建范围仅限于需要管理员批准的组织的细粒度令牌时，令牌会自动进入 **待处理** 状态。在管理员批准之前，它无法访问该组织的资源。当您的令牌被批准或拒绝时，您将收到电子邮件通知。

您可以从令牌列表页面检查状态，待处理的令牌在其权限徽章旁边显示橙色沙漏图标，被拒绝或撤销的令牌显示红色感叹号图标。如果您的令牌被拒绝或撤销，令牌的编辑页面上也会出现红色错误横幅。

> [!注意]
> 如果您是组织的管理员，您创建的范围仅限于该组织的细粒度令牌将自动获得批准 - 无需审核步骤。

### 当您的令牌被拒绝时（团队和企业组织）如果您的令牌被拒绝，您将收到一封电子邮件通知。该令牌保留在您的帐户中，并且仍然可以用于组织外部的资源。被拒绝的令牌稍后可以由管理员批准，从而恢复访问权限，而无需创建新令牌。

当尝试对组织资源使用被拒绝的令牌时，您将收到 `403` 错误。

### 当您的令牌被撤销时（企业组织）

撤销是永久性的。与拒绝不同，撤销的令牌无法恢复。如果您的令牌已被撤销，您必须将其删除并创建一个新令牌。如果组织需要管理员批准，新令牌将以待处理状态开始。

当尝试对组织资源使用已撤销的令牌时，您将收到`403`错误，并显示以下消息：_“您的令牌已被组织管理员撤销，您无法再访问组织资源。请联系他们以获取更多信息。”_

撤销仅影响撤销它的组织。该令牌继续对其作用范围内的所有其他资源正常工作。### 当您的组织仅允许细粒度令牌时（团队和企业组织）

如果您的组织设置了需要细粒度令牌的策略，则在针对该组织的资源使用读/写令牌时，读/写令牌将被拒绝，并出现 `403` 错误。
