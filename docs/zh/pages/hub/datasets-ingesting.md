# 摄取数据集

数据通常以不适合人工智能工作流程的形式存在于数据库或云存储中。
将数据提取到[Hub](https://huggingface.co/datasets)是将其发布为人工智能就绪数据集的好方法，从而实现轻松高效的数据加载、处理以及模型训练和评估。

## 使用`huggingface_hub`

摄取数据最简单的方法是使用`huggingface_hub`上传数据文件。

`huggingface_hub` Python 库提供了丰富的功能集，允许您管理存储库，包括创建存储库和将数据集上传到 Hub。请访问[the client library's documentation](/docs/huggingface_hub/index)了解更多信息。

如果您的数据是静态/冻结的，并且您可以轻松获取具有可用结构（例如用于训练和评估的明确定义的字段）的 Hub 支持的格式（例如 Parquet 或 JSON Lines）的数据本地转储，则这是相关的。

## 使用`dlt`

[dlt](http://github.com/dlt-hub/dlt) 是一个用于数据移动 (ETL) 的开源 Python 库，对于开发人员（及其代理）构建数据管道非常有用。
它可以从不同的源类型获取数据：

* 云存储或文件
* REST API
* SQL数据库
* Python 生成器

源类型示例：

* `filesystem`（包括s3、gs、az、abff等） 
* `sql_database`、`mongodb`、`google_sheets`
* `notion`、`hubspot`、`rest_api`从 [list of sources](https://dlthub.com/docs/dlt-ecosystem/verified-sources) 找到您的源类型并创建您的 `dlt` 项目：

```
dlt init <source-type> filesystem
```

然后，您可以在 dlt 项目的根目录中创建一个配置文件 `.dlt/secrets.toml`，以基于 `hf://` 协议将 Hub 定义为数据集的文件系统目标：

```toml
[destination.filesystem]
bucket_url = "hf://datasets/<namespace>"

[destination.filesystem.credentials]
hf_token = "hf_..."  # Your Hugging Face Access Token
```

命名空间应该是您的用户名或您想要提取数据集的组织/团队的名称。

然后，每个 dlt 数据集都会创建或更新 Hugging Face 数据集存储库。存储库名称为 /，其中与您在 bucket_url（您的组织或团队）中使用的名称相同，并且 是管道的 dataset_name。

这是一个示例管道：

```python
import dlt

@dlt.resource
def my_data():
    # One of the functions auto-generated by `dlt init` that you can customize,
    # or you can define your own python generator function.

    # Here is an example from the `chess` source type:
    for player in ['magnuscarlsen', 'rpragchess']:
        response = requests.get(f'https://api.chess.com/pub/player/{player}')
        response.raise_for_status()
        yield response.json()

# Requires bucket_url = "hf://datasets/<namespace>" in .dlt/secrets.toml
pipeline = dlt.pipeline(
    pipeline_name="my_pipeline",
    destination="filesystem",
    dataset_name="dataset_name",
)

pipeline.run(my_data())
```

自定义`dlt`资源来加载您想要的数据并解析您想要在数据集中发布的字段，例如培训和评估所需的文本。

## 摄取原始数据

如果您提取的原始数据在发布为 AI 就绪数据集之前需要进一步整理，或者您需要类似 S3 的体验，请考虑将它们提取到 [Hugging Face Storage Buckets](./storage-buckets)。如果您的数据已经存在于数据集、模型或空间存储库中，您可以使用 `hf buckets cp` 将其复制到 **服务器端** 存储桶中 - 无需下载或重新上传：

```bash
hf cp hf://datasets/username/my-dataset/ hf://buckets/username/my-bucket/
```

仅迁移 Xet 内容哈希，因此即使非常大的文件也会立即复制。参见[Copying files between repos and buckets](./storage-buckets#copying-files-between-repos-and-buckets)。

## 预定摄取

在集线器上更新同一文件数千次时存在一些限制。
例如，您可能想要摄取几代正在运行的 LLM 推理服务器、实时代理跟踪或正在运行的模型训练的日志。
在这种情况下，将数据作为数据集上传到集线器上是有意义的，但可能很难正确执行。
主要原因是您不想对数据的每次更新进行版本控制，因为这会使 git 存储库无法使用。

提供三个选项：* **使用存储桶而不是数据集存储库：** [Storage Buckets](/docs/hub/storage-buckets) 提供类似 S3 的体验，允许非常频繁地更新文件，因为它们不基于 git。存储桶对于尚未准备好作为数据集发布的数据特别有用，例如仍在发展或需要更多管理的数据。
* **使用 CommitScheduler**：`huggingface_hub` 中的 `CommitScheduler` 提供近乎实时的摄取，以保持数据集存储库的 git 历史记录易于管理。可以将其配置为以分钟为单位定义的时间间隔进行 git 提交。
* **使用 Hugging Face Jobs 来安排摄取脚本**：Hugging Face Jobs 提供了一种在 Hugging Face 基础设施上运行和安排 python 脚本的方法。安排摄取脚本按照使用 Cron 语法定义的时间间隔运行。

### 高频度使用存储桶

与基于 git 的数据集存储库相反，您可以以非常高的速率更新存储桶上的文件，从而提供准实时摄取。

在`huggingface_hub`中使用`batch_bucket_files()`更新存储桶中的文件：

```python
from huggingface_hub import batch_bucket_files

def update_bucket(local_files):
    destinations = [os.path.basename(local_file) for local_file in local_file]
    batch_bucket_files(bucket_id="username/bucket_name", add=[(local_file, dst) for local_file, dst in zip(local_files, destinations)])
```

或者，您可以附加到存储桶中的文件并在每个新项目上添加 `flush()`：

```python
from huggingface_hub import hffs

with hffs.open("buckets/username/bucket_name/texts.jsonl", "a") as f:
    for text in live_texts_stream:
        f.write(json.dumps({"text": text}) + "\n")
        f.flush()
````HfFileSystem` 基于 `fsspec`，其默认块大小为 5MiB，这意味着一旦附加了 5MiB 的完整新数据块，刷新实际上就会上传数据。
如果您想更频繁地上传，请降低 `hffs.open()` 中的 `blocksize`（例如 `hffs.open(..., blocksize=100 * 2 ** 10)` 为 100 kiB）或使用 `f.flush(force=True)`。

Hugging Face 存储基于 Xet，可在附加文件时实现高效的 I/O：上传时会进行重复数据删除，并且仅上传新数据。
在 [buckets documentation on uploads](/docs/hub/storage-buckets#uploading-files) 和 [dataset editing documentation](./datasets-editing#only-upload-the-new-data) 中查找有关在存储桶中进行动态数据摄取的更多信息。

### 使用 `CommitScheduler` 近乎实时

这个想法是运行一个后台作业，定期将本地文件夹推送到集线器。您希望将数据保存到中心（可能有数百万个条目），但不需要实时保存每个用户的输入。相反，您可以将数据本地保存在 JSON 文件中，并每 10 分钟上传一次。例如：

```python
import json
from huggingface_hub import CommitScheduler

folder_path = "path/to/files/to/ingest"
every = 10  # ingest every 10min

with CommitScheduler(repo_id="username/dataset_name", repo_type="dataset", folder_path=folder_path, every=every) as scheduler:
    # Write to the folder to ingest every 10min
    # For example:
    with open(folder_path + "/texts.jsonl", "a") as f:
        f.write(json.dumps({"text": text}) + "\n")
    ...
```

在 [dataset editing](./datasets-editing#only-upload-the-new-data) 的文档中了解如何提取动态数据，而无需每次都重新上传所有内容。

在 [huggingface_hub documentation](/docs/huggingface_hub/guides/upload#scheduled-uploads) 中查找有关计划上传的更多信息。

### 基于 Cron 使用 Hugging Face Jobs

安排 python 脚本根据计划摄取数据

例如每 5 分钟运行一次脚本 `ingest.py`：

```bash
hf jobs scheduled uv run "*/5 * * * *" ingest.py
```声明脚本依赖项[in the header of the script](https://docs.astral.sh/uv/guides/scripts/#declaring-script-dependencies)或使用`--with`。
例如，每天午夜运行 `dlt` 管道：

```bash
hf jobs scheduled uv run --with "dlt[hf]" "0 0 * * *" pipeline.py
```

您可以使用 `hf jobs logs` 或直接在 Hugging Face 帐户的“作业”页面中查看每次跑步的日志。

在 [Jobs documentation](/docs/hub/jobs-overview) 中查找有关拥抱脸部工作的更多信息。
