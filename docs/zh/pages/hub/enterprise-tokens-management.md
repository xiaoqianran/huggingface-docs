# 代币管理

> [!警告]
> 此功能是团队和企业计划的一部分。

令牌管理使组织管理员能够监督组织内的访问令牌，确保对组织资源的安全访问。

> [!注意]
> 有关令牌管理策略生效时的会员体验 - 包括如何检查令牌状态、预期出现哪些错误以及拒绝和撤销如何影响令牌 - 请参阅[Tokens in organizations with token management policies](./security-tokens#tokens-in-organizations-with-token-management-policies)。

## 查看和管理访问令牌

令牌列表功能显示组织内的所有访问令牌。管理员可以：

- 监控代币使用情况并识别或防止潜在的安全风险：
  - 未经授权访问私有资源（“泄漏”）
  - 访问范围过于广泛
  - 代币卫生状况欠佳（例如，代币长时间未轮换）
- 识别不活动或未使用的令牌

    
    

细粒度的令牌显示其特定权限：

    
    

默认情况下，已撤销的令牌在列表中隐藏。使用列表上方的 **显示已撤销的令牌** 开关将它们包含在视图中。无论组织的令牌策略如何，任何已撤销的令牌都会显示 **REVOKED** 状态徽章。 **PENDING**、**APPROVED** 和 **DENIED** 徽章仅出现在启用了“需要管理员批准”策略的组织中，因为这些状态仅由批准流程创建。

## 代币政策

团队和企业组织管理员可以强制执行以下策略：

| **政策** | **无范围（读/写）访问令牌** | **细粒度令牌** |
| ------------------------------------------------- | --------------------------------------- | ----------------------------------------------------------- |
| **允许通过用户访问令牌进行访问（默认）** |授权|授权|
| **只能通过细粒度令牌访问** |未经授权 |授权|
| **需要管理员批准** |未经授权 |未经批准未经授权（管理员创建的除外）|## 检查令牌授权

当令牌策略设置为“需要管理员批准”时，组织管理员可以查看访问组织拥有的资源的所有细粒度令牌的详细信息，并批准或拒绝访问。当新令牌进入待处理状态时，最多 5 位已确认电子邮件地址的组织管理员会收到一条通知，其中包含指向令牌审核页面的直接链接。自动批准令牌时不会发送通知（例如，因为创建者是组织管理员）。

- **待处理**令牌正在等待管理员决定
- **批准** 代币已获得授权并处于活动状态
- **拒绝**令牌已被阻止访问组织资源

当令牌被批准或拒绝时，令牌所有者会收到电子邮件通知。

拒绝不是永久性的：被拒绝的令牌稍后可以由管理员批准，恢复其访问权限。同样，已经批准的令牌可以随时被拒绝，这会立即删除其基于批准的访问权限。

> [!注意]
> 当启用“需要管理员批准”策略时，令牌名称仅对管理员可见。

### 会员被阻止时会看到什么令牌待处理或被拒绝的成员在访问组织资源时会收到 `403` 错误：_“由于组织令牌政策，您的令牌需要先获得组织的批准才能访问此资源。”_

对于待定状态和拒绝状态，错误消息是相同的。要查看状态，成员可以导航到单个令牌的编辑页面。组织管理员令牌管理设置页面显示所有成员令牌的状态徽章。

    
    

## 拒绝与撤销

管理员有两种方法可以删除令牌对组织的访问权限：| **方面** | **否认** | **撤销** |
| ------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| **计划** |团队与企业 |企业计划及以上 |
| **范围** |在审批工作流程中操作 |独立于代币政策 |
| **效果** |阻止或删除基于批准的访问 |无论策略或令牌状态如何，都强制删除访问权限 |
| **可逆吗？** |是的 - 被拒绝的令牌稍后可以被批准 |否 — 即使政策发生变化，撤销状态仍然存在 |
| **其他地方的代币** |对组织外部没有影响 |对组织外部没有影响 |

在批准工作流程中管理访问时使用 **拒绝**（令牌转换为 `denied` 状态，并且可以稍后重新批准）。当您需要永久切断令牌对组织的访问权限时，请使用 **撤销**。

## 撤销令牌> [!警告]
> 此功能是企业计划及以上版本的一部分。

组织管理员可以从令牌详细信息页面撤销任何成员的访问令牌。无论组织是否使用“需要管理员批准”策略，都可以进行撤销。被撤销的令牌无法再访问组织的资源，但可以继续在其他地方工作。令牌所有者在撤销后会收到一封电子邮件通知。

即使组织的令牌策略稍后更改或禁用，已撤销的令牌仍会被撤销。撤销在组织级别是永久性的——不存在不可撤销的操作。如果成员需要恢复访问权限，他们必须删除已撤销的令牌并创建一个新令牌。如果组织使用“需要管理员批准”策略，新令牌将以待处理状态启动并需要管理员批准。令牌已被撤销的成员会收到 `403` 错误，并显示以下消息：_“您的令牌已被组织管理员撤销，您无法再访问组织资源。请联系他们以获取更多信息。”_ 无论组织是否使用“需要管理员批准”策略，都会显示此消息。

### 通过 API 撤销

管理员还可以通过提供原始令牌值以编程方式撤销令牌。这对于自动化工作流程（例如秘密扫描）非常有用，其中检测到泄漏的令牌并需要立即撤销。

```bash
# ORG_NAME should be your organization name and ADMIN_HF_TOKEN an admin's access token
# LEAKED_HF_TOKEN should contain the raw token value to revoke
curl -X POST "https://huggingface.co/api/organizations/${ORG_NAME}/settings/tokens/revoke" \
  -H "Authorization: Bearer ${ADMIN_HF_TOKEN}" \
  -H "Content-Type: application/json" \
    -d "{\"token\": \"${LEAKED_HF_TOKEN}\"}"
```

> [!提示]
> 为了避免泄漏 shell 历史记录或日志中的令牌值，请通过环境变量或文件传递它们，并避免将原始令牌直接粘贴到命令行中。

管理员无法撤销自己的令牌（`LEAKED_HF_TOKEN`不能与上面代码片段中的`ADMIN_HF_TOKEN`具有相同的值）。

> [!注意]
> 此端点仅撤销令牌对您组织的访问权限；该令牌继续为其所有者的其他资源工作。要使到处泄漏的令牌无效，请改用[⟦T6⟧](./security-tokens#revoking-a-leaked-token)，它不需要身份验证并接受一批原始令牌值。

## 程序化代币发行> [!警告]
> 此功能是企业计划及以上版本的一部分。

对于需要以编程方式为其成员颁发访问令牌的组织（例如，用于内部平台、CI/CD 管道或自定义集成），请参阅[OAuth Token Exchange](./oauth#token-exchange-for-organizations-rfc-8693)。此企业计划功能允许您的后端服务为组织成员颁发范围令牌，而无需交互式用户同意。

## 服务帐户

> [!警告]
> 此功能是企业计划及以上版本的一部分。

对于由组织而不是个人成员拥有的自动访问，管理员可以创建 [Service Accounts](./enterprise-service-accounts) 并颁发适用于组织资源的细粒度令牌。
