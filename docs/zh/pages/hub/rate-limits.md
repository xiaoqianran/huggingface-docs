# 集线器速率限制

为了保护我们平台的完整性并确保尽可能多的 AI 社区成员可用，我们对向 Hugging Face Hub 发出的所有请求实施速率限制。

我们为不同类别的请求定义不同的速率限制。我们区分三个主要的桶：

- **集线器 API**
  - 例如模型或数据集搜索、存储库创建、用户管理等。属于此存储桶的所有端点都记录在[Hub API Endpoints](./api)中。
- **解析器**
  - 它们都是路径中包含 `/resolve/` 段的 URL，这些 URL 提供来自 Hub 的用户生成的内容。具体来说，这些是由开源库（transformers、datasets、vLLM、llama.cpp 等）或 AI 应用程序（LM Studio、Jan、ollama 等）构建的 URL，用于从 HF 下载模型/数据集文件。
  - 具体来说，这是我们的 OpenAPI 规范中记录的 ["Resolve a file" endpoint](https://huggingface-openapi.hf.space/#tag/models/get/apiresolve-cachemodelsnamespacereporevpath)。
  - 解决请求被社区大量使用，由于我们优化了基础设施以最大效率地为他们服务，因此解析器的速率限制是最高的。
- **页面**
  - 我们在 Huggingface.co 上托管的所有网页。- 通常 Web 浏览请求是由人类发出的，因此速率限制不需要与上述编程端点一样高。

> [!提示]
> 所有值均在 5 分钟窗口内定义，从应用程序或开发人员的角度来看，这允许一定程度的“突发”。

如果您、您的组织或您的应用程序需要更高的速率限制，我们鼓励您将帐户升级到 PRO、Team 或 Enterprise。我们优先考虑来自 PRO、团队和企业客户的支持请求 - 请参阅[Rate limit Tiers](#rate-limit-tiers) 中的内置限制。

## HTTP 标头每当您或您的组织达到速率限制时，您都会收到 **429** `Too Many Requests` HTTP 错误。

我们实现了标题为“HTTP 的 RateLimit HTTP 标头字段”的 [IETF draft (Version 9)](https://datatracker.ietf.org/doc/draft-ietf-httpapi-ratelimit-headers/) 中描述的机制（也称为 `draft-ietf-httpapi-ratelimit-headers`）。

目标是定义标准化的 HTTP 标头，服务器可以使用这些标头来通告配额/速率限制策略并向客户端传达当前使用情况/限制，以便它们避免受到限制。

准确地说，我们实现了以下标头：

|标题 |目的/意义|
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **`RateLimit`** |当前窗口允许的总速率限制。 “您可以执行多少（此类）请求。”                      |
| **`RateLimit-Policy`** |本身带有速率限制策略（例如“每 5 分钟 100 个请求”）。内容丰富；显示客户受哪些政策约束。 |

一组例子如下：|标题 |示例|
| ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| **`RateLimit`** | `"api\|pages\|resolvers";r=[remaining];t=[seconds remaining until reset]` |
| **`RateLimit-Policy`** | `"fixed window";"api\|\pages\|resolvers";q=[total allowed for window];w=[window duration in seconds]` |

## 如果我受到速率限制怎么办

首先，确保您始终传递 `HF_TOKEN`，并将其传递到下游到从集线器下载_stuff_的所有库或应用程序。

这是用户受到速率限制的首要原因，并且是一个非常容易解决的问题。

尽管通过了`HF_TOKEN`，如果您仍然受到费率限制，您可以：- 将您的请求分散到更长的时间内
- 尽可能用解析器调用替换集线器 API 调用（解析器速率限制更高且更优化）。
- 升级到 PRO、Team 或 Enterprise。

## 使用 `huggingface_hub` 进行智能速率限制处理

Hub Python 库[⟦T12⟧](https://huggingface.co/docs/huggingface_hub/index)（版本 **1.2.0+**）包括针对速率限制错误的智能重试处理。

当发生 429 错误时，SDK 会自动解析 `RateLimit` 标头，以提取速率限制重置之前的准确秒数，然后在重试之前精确等待该持续时间。这适用于文件下载（即解析器）和分页 Hub API 调用（列表模型、数据集、空间等）。

**我们强烈建议对集线器的所有编程访问使用`huggingface_hub`**，以便从这种优化的重试行为中受益，并避免实施自定义速率限制处理。
